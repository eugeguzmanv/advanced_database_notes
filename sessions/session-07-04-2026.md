# Session – 2026-04-14

## Topics covered
- **Indexes:** Store column values + ROWID for direct data access.
- **Full Table Scan (FTS):** Sequential reading of all table blocks.
- **CBO (Cost-Based Optimizer):** Calculates the most efficient execution plan based on I/O costs.
- **B-Tree:** Root/branch/leaf structure for logarithmic search times.
- **Composite Indexes:** Multi-column indexes where column order dictates efficiency.

## What I understood
- Indexes are for high-selectivity queries. For low cardinality or large data retrievals, FTS is faster to avoid table-hopping.
- Applying functions (e.g., `TRUNC()`) to a column in a `WHERE` clause disables standard index usage.
- Composite indexes `(A, B)` require the leading column `(A)` in the search criteria to navigate the tree efficiently.

## What is still confusing
