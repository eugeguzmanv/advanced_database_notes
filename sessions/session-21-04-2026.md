## Topics covered
- **Database Transactions:** Grouping SQL statements to succeed or fail as a single block (`BEGIN`, `COMMIT`, `ROLLBACK`).
- **ACID Properties:** Core requirements for reliable transactions (Atomicity, Consistency, Isolation, Durability).
- **Stored Procedures:** Encapsulating complex, parameterized logic into reusable server-side objects.
- **Autocommit:** Instant automatic commits vs. manually controlled transaction boundaries.

## What I understood
- Transactions prevent partial database updates. If any step fails, the entire process rolls back.
- `BEGIN TRANSACTION` and `COMMIT` ensure related updates happen simultaneously or not at all.
- Stored Procedures keep complex logic on the server, making code reusable and easier to maintain.
- **ACID in Practice:**
  - **Atomicity:** The "All or Nothing" rule.
  - **Consistency:** Data moves between valid states, strictly following constraints.
  - **Isolation:** Running transactions are hidden from each other until committed.
  - **Durability:** Committed data is permanently saved, even during a system crash.
