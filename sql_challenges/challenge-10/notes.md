```
class Comment(Base):
    __tablename__ = "comments"

    id = Column(Integer, Identity(always=True), primary_key=True)
    task_id = Column(Integer, ForeignKey("tasks.id", ondelete="CASCADE"))
    user_id = Column(Integer, ForeignKey("users.id"))
    content = Column(String(1000), nullable=False)
    created_at = Column(DateTime, default=datetime.utcnow)

    __table_args__ = (CheckConstraint("content != ''", name='ck_comment_content_not_empty'),)

    # Relationships
    task = relationship("Task", back_populates="comments")
    user = relationship("User", back_populates="comments")
```

1. What relationships should `Comment` have?
- A relationship to Task
- A relationship to User
Because each comment belongs to a task, and each comment is written by one user.

2. Should `Task` have a `comments` relationship?
Yes, a task can contain many comments, so comments = relationship("Comment", back_populates="task")

3. What should happen to comments when a task is deleted?
Comments should also be deleted automatically, that is why we use: task_id = Column(Integer, ForeignKey("tasks.id", ondelete="CASCADE"))

It applies the migration changes to the database.
Example:
creates tables
adds columns
adds constraints

2. What does `downgrade()` do?
It reverses the migration.

drops tables
removes columns
removes constraints

```
    # Close one task

    session.commit()

    print(f"Task closed: {task1.title}")

    # Delete lowest priority task
```

## Exercise 5: Questions
1. Why use ORM instead of raw SQL?
ORM allows developers to work with Python objects instead of writing SQL manually.
The benefits are that we have a cleaner code, it allows to do easier maintenance, have more portability, and automatic relationships.

2. Why use migrations?
Migrations track and apply schema changes safely and consistently. It allows us to have a version control for databases, rollback support, and team synchronization.

3. When would you rollback?
When a migration contains errors, the deployment fails, and the schema changes must be undone.

4. Difference between `add()` and `commit()`?
add(): Stages objects in the session.
commit(): Permanently saves changes to the database.

5. Why are relationships useful?
Relationships allow automatic navigation between related objects, without manually writing SQL joins.
